\chapter{\cmm{}: fundamentos}
\label{cap:cmm-fundamentos}

A \cmm{} (lê-se \enquote{C mais-menos}; nos arquivos, extensão \file{.cmm}) é a linguagem principal do SAPHO: um dialeto de C criado pelo NIPS-CERN, enxuto o bastante para virar hardware eficiente e expressivo o bastante para algoritmos de processamento de sinais, com números complexos como tipo nativo e álgebra linear em notação de Dirac. Este capítulo apresenta a estrutura de um programa; os seguintes cobrem tipos, operadores, entrada e saída, biblioteca e recursos avançados.

\begin{nota}
Tudo o que está nesta parte foi extraído da gramática oficial do compilador, nos arquivos \file{CMMComp.y} e \file{CMMComp.l} do repositório \repo{yanc}, cadeia de ferramentas na versão 5.3; o que a versão 7.1 acrescentou, os \textit{links} entre processadores, está na Seção~\ref{sec:links}. Quando o manual diz que algo não existe na linguagem, é porque não existe na gramática, e o compilador rejeitará o código.
\end{nota}

\section{A estrutura de um programa}

Um programa \cmm{} é uma sequência de três tipos de elemento, em qualquer ordem: diretivas, que são as linhas iniciadas por \code{\#}; declarações de variáveis globais; e funções. O ponto de entrada é obrigatório, uma função \code{void main()}, e a sua ausência encerra a compilação com erro.

A forma canônica de um programa SAPHO coloca as diretivas no topo, configurando o processador, e em seguida o \code{main()} com um laço infinito \code{while (1)}; afinal, o programa modela um circuito que roda continuamente, processando amostras para sempre. O exemplo abaixo é o \code{media_movel}, o processador que acompanha o manual inteiro, um filtro de média móvel de quatro amostras, no arquivo \file{media_movel.cmm}:

\begin{lstlisting}[style=cmm]
#NUBITS 16
#NUIOIN 1
#NUIOOU 1
#NBMANT 10
#NBEXPO 5

void main()
{
    int x[4];    // historico das ultimas 4 amostras
    int soma;

    while (1)
    {
        x[3] = x[2];          // desloca o historico
        x[2] = x[1];
        x[1] = x[0];
        x[0] = in(0);         // le nova amostra da porta 0

        soma = x[0] + x[1] + x[2] + x[3];
        out(0, soma >> 2);    // media = soma/4, sem usar divisor
    }
}
\end{lstlisting}

O nome do processador não aparece no código: é o nome do arquivo. O \file{media_movel.cmm} gera o processador \code{media_movel} e o módulo Verilog \code{media_movel}.

Repare em duas escolhas típicas de quem escreve para o SAPHO. O histórico é um \textit{array} deslocado à mão, e a divisão por quatro é um deslocamento de bits (\code{>> 2}); assim o processador gerado não precisa instanciar um divisor, que é um dos blocos mais caros da ULA.

\section{Diretivas: configurando o processador no próprio código}
\label{sec:diretivas}

As diretivas são linhas que começam com \code{\#}, uma por linha, sem ponto e vírgula ao final. São elas que definem a arquitetura do processador a ser gerado; o nome vem do arquivo, e a antiga diretiva \code{\#PRNAME}, se aparecer, é erro de compilação. Quando você cria um processador pela AURORA (Capítulo~\ref{cap:criando-processadores}), o formulário preenche essas diretivas no \file{.cmm} inicial; a partir daí o arquivo é a fonte da verdade, e editar uma diretiva muda o processador na compilação seguinte. A referência completa, com os valores assumidos quando cada diretiva é omitida, está no Apêndice~\ref{ap:diretivas}; as mais usadas são \code{\#NUBITS}, a largura da palavra, \code{\#NBMANT} e \code{\#NBEXPO}, o formato do ponto flutuante, e \code{\#NUIOIN} e \code{\#NUIOOU}, as quantidades de portas.

\begin{aviso}
Lembre da restrição estrutural: \texttt{NUBITS} deve ser igual a \texttt{NBMANT} mais \texttt{NBEXPO} mais um. No exemplo acima, $16 = 10 + 5 + 1$. A AURORA valida a igualdade ao criar o processador, mas quem edita as diretivas à mão responde por mantê-la.
\end{aviso}

Existem ainda duas diretivas comportamentais, que aparecem no meio do código e marcam pontos do programa: \code{\#PRACA}, o ponto de retorno da interrupção, e \code{\#TOAQUI}, o marcador refletido no pino \code{cheguei}. Ambas são explicadas no Capítulo~\ref{cap:cmm-avancado}.

\section{Constantes com \texttt{\#define}}

A \cmm{} tem um pré-processador mínimo embutido: \code{\#define NOME corpo} define uma constante simbólica, expandida onde o nome aparecer.

\begin{lstlisting}[style=cmm]
#define SCALE  3
#define OFFSET 7

void main()
{
    int x;
    while (1)
    {
        x = in(0);
        x = x + SCALE;
        out(0, x);
        x = x + OFFSET;
        out(0, x);
    }
}
\end{lstlisting}

Três limitações distinguem esse pré-processador do C tradicional: só existem \textit{defines} de objeto, de modo que macros com argumentos, como \code{\#define DOBRO(x) ((x)*2)}, não são aceitas; não há \code{\#include} nem \code{\#ifdef} no lado \cmm{}, embora o fluxo C++ tenha pré-processador completo (Capítulo~\ref{cap:cmm-avancado}); e o limite é de 256 \textit{defines} por programa. O editor da AURORA reconhece os seus \code{\#define} e os colore como constantes conforme você digita.

\section{Comentários}

Como em C: \code{//} comenta até o fim da linha, e \code{/* ... */} comenta blocos.

\section{Onde o arquivo vive}

Dentro de um projeto AURORA, o código de cada processador fica em \file{<projeto>/<processador>/<processador>.cmm}, ao lado dos arquivos que inicializam vetores e dos estímulos \file{input_<i>.txt}. A compilação põe tudo o que gera, o \textit{assembly}, o Verilog, as imagens de memória e o \textit{testbench}, na pasta de saída \file{<projeto>/<processador>/<processador>/} (Capítulo~\ref{cap:compilacao}).
