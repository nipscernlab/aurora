# PRISM symbol standard

How every PRISM (RTL viewer) symbol should look, so **anyone studying the
schematic understands what each element is and does at a glance** — and so the
whole datapath looks like one professional, deliberate family.

The flagship that defines it is [`ula_mux.svg`](ula_mux.svg) — the most complex
SAPHO cell (a 42-to-1 result multiplexer) — generated by
[`scripts/prism-skin-standard.js`](../../scripts/prism-skin-standard.js). That
script **is** the standard: edit the tokens/families/geometry there, not the
SVGs by hand.

> A skin is a netlistsvg fragment keyed by `s:type` (+ `<s:alias>` fallbacks),
> merged over the stock netlistsvg skin at compile time by `getDefaultSkinData`
> in `main/ipc/prism.js`.

## The eight principles

1. **Silhouette = meaning.** The body shape states the function before any label
   is read. A *selector/mux* is a right-pointing pentagon (flat input side →
   narrowing to one output apex). One silhouette per element class (library
   below) so the same shape always means the same thing.
2. **It's a chip.** The body is a **dark card** (`--prism-card`) so labels always
   read with contrast regardless of the host background — like an IC on a board.
3. **Branding is restrained.** Only the `processor` top cell carries a faint,
   single-tone watermark — the **SAPHO** "S" (`assets/icons/sapho_aurora_icon.svg`)
   in its open area. Other cells carry no watermark (the PRISM dispersion mark
   read as a smudge in the smaller cells). No header motif, no colour strip.
4. **Flow left → right; control enters north.** Data inputs sit west (`s:x=0`),
   the result leaves east (`s:x=width`), the select/enable enters from the **top**
   in the **control accent (violet)** — control is always visually separate from
   data.
5. **Ports grouped by semantic family**, colour-coded, each cluster bracketed and
   headed — exactly as the Verilog groups them. **Colour encodes family.**
6. **Typography.** ONE sans family (`Segoe UI`/system-ui) for all UI text
   (title, headers, labels); **mono only for port identifiers**. Clear size/weight
   hierarchy. _Never leave text without a `font-family` — it falls back to serif
   (Times); that was the original mistake._
7. **Theme-driven colour, NO gradients.** Every colour is a CSS var with a hex
   fallback. **Do not use `<linearGradient>`/root `<defs>`** — PRISM merges only
   the `<g s:type>` block, so anything outside it is dropped. Build spectra from
   solid colour segments.
8. **Crisp geometry** on an integer grid: 1.4px body stroke, 7px row pitch,
   rounded joins.

## Colour roles

| role | token | fallback |
| ---- | ----- | -------- |
| card body | `--prism-card` | `#0E1320` |
| body stroke | `--prism-module-stroke` | `#5FE0B0` (mint) |
| title / glyph | `--prism-module-glyph` | `#EAF2EE` |
| instance ref / accent | `--prism-module-accent` | mint |
| **control** (select/enable) | `--accent` | `#8E83E8` (violet) |
| pin label | `--prism-port-label` | `#AEB6C4` |
| subtitle | `--text-secondary` | `#9CA1AE` |

## Silhouette library (body shape per element class)

| class | shape | examples |
| ----- | ----- | -------- |
| selector / mux | right-pointing pentagon + select notch | `ula_mux`, `norm_mux`, `mux` |
| ALU / datapath op | pentagon with operand V-notch + result arrow | `ula`, `ula_add`, `ula_fmlt` |
| register / latch | rounded card with a clock-edge triangle on `clk` | `pc`, `stack`, `dff` |
| memory | rounded card with a stacked-plates edge | `mem_data`, `mem_instr` |
| decoder / control | rounded card, control north, fanned outputs east | `instr_dec`, `addr_dec`, `io_ctrl` |
| FIFO / buffer | rounded card with flow chevrons | `myFIFO` |

## Hard rules (don't break these)

- **`s:pid` MUST equal the Verilog port name exactly** — it's what ELK routes to.
- **Exclude `` `ifdef YANC_SIM_VIS `` ports** (sim-visibility taps like `sim`):
  yosys reads the HDL without that define for PRISM, so an anchor for a port not
  in the netlist makes ELK abort with *"Referenced shape does not exist"*.
- **No gradients / no root `<defs>`** (principle 7). **Always set `font-family`**
  (principle 6). Keep `s:type` + every `<s:alias>`.

## Authoring / rolling out

`scripts/prism-skin-standard.js` parses every `components/HDL/*.v` module and
renders it — selectors (`ula_mux`, `norm_mux`) as the pentagon, everything else
as a clean chip card — so the whole datapath is one consistent family. It picks
the class accent + watermark automatically from the module name.

```sh
node scripts/prism-skin-standard.js            # regenerate EVERY SAPHO module skin
node scripts/prism-skin-standard.js --only pc  # just one
node scripts/prism-skin-standard.js --print pc # dump one to stdout
```

> PRISM CSS (`html/prism/prism.css`) backs the look: it defines `--prism-card`
> and `--prism-port-label`, and crucially does NOT `!important` the text
> `font-family` (so the skins' inline mono port labels win) and never strokes a
> `<circle>` for our pins (we use small `<rect>`s on purpose).

**Preview** a skin on the PRISM dark theme by wrapping it in an HTML page that
defines the `--prism-*` / `--aurora-*` vars and giving the `<svg>` a `viewBox`,
then screenshotting headless (that's how the flagship was tuned). The
hand-crafted symbols (`core`, `ula`, `processor`, `instr_dec`, `addr_dec`,
`myFIFO`) and the auto-baselines from `gen-prism-skins.js` are the backlog to
bring up to this standard — one element class at a time.
