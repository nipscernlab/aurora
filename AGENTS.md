# Working on AURORA

This file is the entry point for anyone who changes this repository, a person or a coding agent. It says what AURORA is, where each rule lives and the one path every change takes. It links to documents rather than repeating them, so that each rule has one copy.

## What AURORA is

The desktop IDE of the SAPHO platform, from NIPS-CERN: writing C±, compiling with YANC, assembling, simulating, reading waveforms and inspecting RTL behind one interface. It is an Electron application with Monaco as its editor, and it runs on Windows. It carries Aurora Intelligence, the assistant built on the Claude Agent SDK that operates the IDE through its own tools. Releases are published from [nipscernlab/sapho](https://github.com/nipscernlab/sapho).

The toolchain AURORA drives (YANC, Icarus, Verilator, GTKWave, Surfer and the rest) is not in this repository: `npm run bootstrap` downloads it into `components/`.

The maintainers are named in [`.github/CODEOWNERS`](.github/CODEOWNERS).

## The one command

There is no single command yet that runs what CI runs. The steps CI gates on are in [`.github/workflows/ci.yml`](.github/workflows/ci.yml); before every push, run at least these:

```sh
npm ci
npm run build:ts
npx eslint . --max-warnings=0
node scripts/check-types.js
npm run test:coverage && npm run coverage:diff
npm run test:e2e
```

A change that touches compilation, simulation or any command line the IDE builds also runs `npm run test:toolchain`, which drives the real binaries and needs the full `components/` tree.

## Rules of the laboratory

These come from the [nipscernlab guidelines](https://github.com/nipscernlab/.github/blob/main/GUIDELINES.md) and the [writing style](https://github.com/nipscernlab/.github/blob/main/STYLE.md). They apply to people and agents alike.

1. Work on a branch of this repository named `<login>/<topic>`, and reach `main` through a pull request. Nobody pushes to `main` directly.
2. A pull request is merged only when the required CI checks pass. A pull request from anyone other than an organization owner also needs the approval of the maintainer named in `CODEOWNERS`. If you need a merge, ask the maintainer.
3. Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/). The body says why.
4. Code and documentation move together. If a change makes a sentence in the README, the manual or any document untrue, the same pull request fixes it. An outdated document is a defect, like a failing test.
5. Every change comes with the tests that show it works.
6. No credential enters the repository: no password, API key, token, connection string or private key. A credential that reaches a commit is reported at once so it can be revoked.
7. Data from the ATLAS collaboration enters this repository only under the collaboration policy.
8. Facts about SAPHO, C±, YANC and the other projects of the laboratory come from their manual and their repositories, not from general knowledge: none of them exists outside this organization. An inference is written as an inference.

## What an agent must never do

- Merge a pull request, push to `main`, or rewrite its history.
- Change repository or organization settings, rulesets, secrets, workflows' permissions or collaborators.
- Disable, skip or weaken a test, a check or a lint to make CI pass.
- Write a fact, a number or a result it has not verified. Check it, or say it was not checked.

## Rules of this repository

1. **Read before refactoring.** [`CODEMAP.md`](CODEMAP.md) first; [`ARCHITECTURE.md`](ARCHITECTURE.md) before touching the renderer modules it lists, and walk its final checklist before opening the pull request.
2. **A file you edit leaves in TypeScript.** If it is still `.js`, convert it whole, in strict mode, in a commit of its own (`npm run converter:ts -- <file.js>`), and make the change in a second commit. Generated `.js` is never committed. [`CONTRIBUTING.md`](CONTRIBUTING.md) has the detail.
3. **Every changed line is exercised by a test.** `npm run coverage:diff` lists the ones that are not. Code no unit test can reach gets an end-to-end test and v8's `ignore start` and `ignore stop` comments with the reason beside them; that is the only way past the check.
4. **The interface is bilingual.** Every string a user sees exists in English and in Portuguese, and `node scripts/check-i18n.js` keeps the two in step.
5. **Generated references stay generated.** The Aurora Intelligence tools reference is checked by `node scripts/gen-ai-tools-doc.js --check`; regenerate it, never edit it by hand.
6. **Aurora Intelligence learns C± from the YANC it ships with.** When the bundled YANC changes, `resources/sapho_rules.json` is regenerated with `npm run rules:sync` against that YANC, and every version the prompt in `js/ai/system_prompt.ts` cites is checked against it, in the same pull request.
7. **No new hard-coded colours, durations or cross-file globals.** CI checks both; use the design tokens and explicit imports.
